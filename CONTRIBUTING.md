# Contributing

Start from the art direction, asset specification and [future-content queue](docs/FUTURE_CONTENT.md). Pick one documented job and state its ID, deliverable and acceptance criteria in your PR. An issue can be used to propose additional work.

Submit new art as a versioned file; preserve earlier concepts unless removal is intentional. Update the asset catalog with actual dimensions, hash, status, and limitations.

Only contribute material you are entitled to share. Do not include proprietary game files, third-party source art, credentials, or personal machine paths. Describe inspiration without claiming official affiliation.

Pull requests should include a preview, the intended in-game use, and the checks performed. Keep concept review separate from production readiness.

## Ready-to-use art briefs

Start with [the contributor art jobs](docs/art-jobs/README.md). They include copyable generation prompts, exact export grids, anchors, timings, runtime checks and a submission schema. Outside contributors should submit a PR per bounded job. Maintainer changes are committed and pushed directly to main.

The next planned map is the Ruined Cloister. Flying Bell Moth, healing vial and lever/grate are its first content priorities. Later briefs cover the Flooded Cistern, Bell Tower, new melee/ambush enemies and a boss. The queue also includes optional weather, cloth, sound and UI work. Describe art-only candidates and working gameplay integration separately, including system dependencies that remain unimplemented.

Coding contributors can start with the [connected-room implementation prompt](docs/ROOM_TRANSITION_BRIEF.md), which defines transition, camera, checkpoint and per-room persistence evidence.

All original submissions and variants must be retained. Earlier guidance about intentional removal does not permit discarding unused art: add versioned derivatives and preserve originals, including candidate or rejected outputs.
